# 医院推荐与地图接入说明

> 对应功能：报告卡片「医院推荐」按钮
> 目标：用户允许定位后，按距离推荐附近医院；可打开真实地图；没有定位/没有后端时也能演示。

---

## 一、现在的实现

### 1.1 用户流程

```text
报告卡片 → 点“医院推荐”
  → 弹窗询问：使用当前位置 / 手动选择区域
  → 浏览器 Geolocation 获取 lat/lng
  → 后端 /api/v1/hospitals/nearby 计算距离并排序
  → 展示医院名称、等级、距离、地址、挂号方式
  → “打开地图”跳转高德地图标记页
```

如果用户拒绝定位、浏览器不支持定位、或单文件离线打开：

```text
→ 提示“没有获得位置权限”
→ 先展示福州市中心附近医院
→ 同时提供“手动选择区域”（鼓楼/台江/仓山/晋安）
```

### 1.1.1 定位不准时：输入具体位置

如果浏览器定位精度 > 1.2km，前端不会直接拿这个点推荐医院，而是提示：

> 定位精度约 ±X km，请补充具体位置

用户可以在输入框输入：

```text
福州大学旗山校区
```

后端调用高德 **输入提示 API** 解析成真实坐标：

```text
GET /api/v1/hospitals/geocode?address=旗山校区
```

返回：

```json
{
  "label": "福州大学旗山校区(西门)",
  "address": "上街镇乌龙江北大道2号",
  "latitude": 26.057439,
  "longitude": 119.193555,
  "source": "amap"
}
```

然后按这个点推荐医院。实测“旗山校区”会得到：

- 福建医科大学附属协和医院(旗山院区) 约 1.2km
- 福建中医药大学附属第三人民医院 约 2.2km

> 为什么不用大模型直接生成经纬度？
> 大模型可以理解“旗山校区”这种口语，但**经纬度必须来自真实地图数据**，否则就是编造。
> 所以这里的“智能解析”用高德输入提示 API；大模型只适合做口语归一化，不适合直接产坐标。

### 1.1.2 保存位置与“使用历史位置”

解析成功后，页面会询问：

> 保存这个位置？下次打开医院推荐时可以直接使用：福州大学旗山校区(西门)

- 点“保存”→ 写入浏览器 `localStorage`，同时同步到后端 `/api/v1/preferences/location`；
- 点“取消”→ 只本次使用，不保存；
- 可随时点“删除”清除（本地和后端一起删）；
- 医院推荐弹窗右侧按钮是“使用历史位置”，有记录时直接复用，没有时显示空状态，不再弹出区域按钮。

#### 为什么保存的位置有时“不见了”？

`localStorage` 按**打开方式（origin）**隔离：

- `http://127.0.0.1:8000` 保存的位置；
- `file:///.../门诊排队-Alpha演示.html` 保存的位置；

二者互相看不到，对话历史也是一样。  
为了解决这个问题，后端新增了单行表 `saved_location`：

- 前端保存时同时写本地和后端；
- 打开弹窗时，本地没有记录就去后端取；
- 因此只要后端在运行，localhost 和双击 HTML 可以共享同一个“上次位置”。

注意：这是**单机演示级**设计，后端只存一条位置，多个用户会共用；正式上线应按用户 ID 隔离。

另外：

- 地址必须先解析成功，才会出现“保存这个位置？”；
- 必须点“保存”，点“取消”不会保存；
- 浏览器无痕模式/禁用本地存储时，仍有后端兜底；后端也不可用时会提示仅本次会话有效。

### 1.1.3 单文件离线也能解析常见地点

单文件版不依赖后端，内置了以下地点：

- 旗山校区 / 大学城 / 福州大学
- 鼓楼区 / 台江区 / 仓山区 / 晋安区

输入“旗山校区”会直接按 `26.057439, 119.193555` 推荐，第一条是协和旗山院区约 1.2km。  
其他任意地址才需要后端 + 高德输入提示。

### 1.1.4 自动重连后端

- 页面加载时探测 `http://127.0.0.1:8000` 和 `http://localhost:8000`；
- 后端没启动时进入本地演示，但每 5 秒静默探测一次；
- 后端启动后自动切回在线，无需刷新页面；
- 切换浏览器标签/窗口回到页面时也会立即重试；
- 后端 CORS 已允许 `file://` 的 `Origin: null`，并返回 `Access-Control-Allow-Private-Network: true`，避免 Chrome 私有网络访问拦截。

### 1.2 后端接口

`GET /api/v1/hospitals/nearby?lat=26.074&lng=119.296&limit=6`

返回：

```json
{
  "origin": { "lat": 26.074, "lng": 119.296 },
  "source": "local",
  "message": "",
  "items": [
    {
      "name": "福建省立医院",
      "level": "三甲",
      "address": "福州市鼓楼区东街134号",
      "latitude": 26.0813,
      "longitude": 119.2986,
      "distance_km": 0.3,
      "registration_channel": "114预约挂号平台/医院公众号",
      "registration_url": "",
      "map_url": "https://uri.amap.com/marker?position=119.298600,26.081300&name=...",
      "source": "local"
    }
  ]
}
```

- 距离计算：Haversine 公式，单位 km；
- 排序：由近到远；
- `limit` 最大 20；
- 坐标缺失的医院会被跳过。

### 1.3 数据表

`hospitals` 表新增：

- `address`
- `latitude`
- `longitude`

当前种子 6 家福州三甲医院：

- 福建医科大学附属协和医院
- 福建医科大学附属第一医院
- 福建省立医院
- 福州市第一医院
- 福建省人民医院
- 福建省妇幼保健院

> 坐标是 GCJ-02 近似值，仅用于课程演示的“按距离排序”。
> 上线前必须按医院官方地址校准；不要把它当成精确导航坐标。

### 1.4 地图链接

不依赖 JS SDK / Key，直接使用高德 URI：

```text
https://uri.amap.com/marker?position=经度,纬度&name=医院名&coordinate=gaode&callnative=1
```

在手机浏览器里会尝试唤起高德 App；没有 App 时打开高德网页。
百度/腾讯地图也可以按同样方式拼 URI，改 `hospitalMapUrl()` 即可。

## 二、接真实地图 POI（可选）

本地医院表只有 6 家，适合演示。如果要“真实周边医院搜索”，推荐用高德 **Web 服务 API**，Key 只放后端，不暴露给前端。

### 2.0 费用与免费额度（先看这段）

- **Key 本身免费**，收费的是 API 调用量；
- 按高德 2025-05-20 起执行的价格：个人认证开发者、**非商业目的**：
  - 基础搜索服务（含关键字/周边/多边形/ID/输入提示）：**5,000 次/月**；
  - 基础 LBS（路径规划/地理编码/坐标转换等）：150,000 次/月；
  - 基础地图定位：1,500,000 次/月；
- 免费月配额自认证之日起 **1 年**；超出后基础搜索约 **30 元/万次**（以控制台账单为准）；
- **课程项目/个人学习**通常用不满 5,000 次/月，免费额度足够；
- **商业用途**（对外收费、企业系统、给第三方交付等）需要购买技术服务许可，不能直接拿个人免费 Key 商用。

> 如果你不想申请 Key：本项目默认的“6 家本地医院 + 高德地图 URI 跳转”**完全不需要 Key，也不产生 API 费用**，课程演示够用。
> 只有勾选“周边搜索真实 POI”时才需要 Key。

### 2.1 申请 Key

1. 注册/登录高德开放平台：https://console.amap.com/dev/id
2. 完成个人实名认证（个人认证免费；企业认证配额更高）
3. 进入「应用管理」：https://console.amap.com/dev/key/app
4. 创建新应用 → 在应用下「添加 Key」
5. **服务平台选「Web 服务」**（不要选「Web 端(JS API)」）
6. 复制 Key，填入 `.env` 的 `AMAP_API_KEY`

> 官方步骤：https://lbs.amap.com/api/webservice/create-project-and-key

### 2.2 配置

`.env`：

```ini
AMAP_API_KEY=你的高德Web服务Key
```

重启后端。之后 `/api/v1/hospitals/nearby` 会优先调用高德：

```text
https://restapi.amap.com/v3/place/around
  ?key=...
  &location=经度,纬度
  &keywords=医院
  &types=090100
  &radius=15000
  &offset=6
  &page=1
  &extensions=all
```

高德返回 `pois` 后，后端会转成同一套 `HospitalItem`，前端无感。

如果 Key 未开通、限流、网络失败，后端自动回退本地医院表，不会让页面报错。

### 2.3 安全注意

- **不要把 Key 写进前端 `app.js`**；
- 高德控制台给 Key 配 IP 白名单/域名限制；
- 不要把 `.env` 提交到 GitHub；
- 注意高德 API 的配额和商用授权条款。

### 2.4 用 JS SDK 嵌入地图（另一种方案）

如果要在页面里直接显示地图、拖拽、路线规划，而不只是跳转：

1. 在高德控制台创建 **Web 端（JS API）** Key；
2. 在页面引入：

```html
<script src="https://webapi.amap.com/maps?v=2.0&key=你的JSKey"></script>
```

3. 用 `AMap.Map` + `AMap.PlaceSearch` 显示周边医院；
4. 需要配置域名白名单，并且 Key 会暴露在前端，务必限制配额/域名。

课程演示更推荐当前的“后端 Web 服务 + URI 跳转”方案：不用管域名白名单，也不会把 Key 暴露给前端。

## 五、定位与距离的准确性

这是最容易产生误解的地方，必须说清楚：

### 5.1 高德 Key 的作用

Key 解决的是**真实 POI 数据**：

- `/api/v1/hospitals/nearby`：按坐标返回真实医院名称、地址、坐标；
- `/api/v1/hospitals/geocode`：把“旗山校区”这类地址解析成真实坐标；
- 比本地 10 家医院更完整的周边结果；
- 地图链接。

Key **不能**：

- 让浏览器定位变准；
- 把直线距离变成导航距离；
- 保存位置或聊天记录（那是 `localStorage` 的事）。

如果只做课程演示，本地 10 家医院 + 内置常见地点已经够用；  
Key 是“更真实的 POI 和任意地址解析”，不是“更精确的定位”。

### 5.2 浏览器定位为什么不靠谱

- 浏览器 Geolocation 可能来自 GPS、Wi-Fi、基站或 IP；
- 桌面浏览器经常只给到城市/街区级精度；
- `coords.accuracy` 是“置信半径”，可能几十米，也可能几公里；
- 室内、地下、电脑无 GPS 时误差更大。

当前前端做了三件事：

1. 读取 `coords.accuracy`，在标题下显示“定位精度约 ±Xm/km”；
2. 精度 > 1.5km 时显示黄色警告，建议手动选择区域；
3. 提供“手动选择区域”，不强迫使用浏览器定位。

### 5.3 坐标系转换

- 浏览器 Geolocation：WGS-84；
- 高德 POI / 距离：GCJ-02；
- 不转换会有几十到几百米偏移，足以让“最近医院”排序出错。

前端 `wgs84ToGcj02()` 已做转换；手动选择的鼓楼/台江/仓山/晋安坐标本身是 GCJ-02，不再转换。

### 5.4 距离是直线距离

当前展示的是 **Haversine 直线距离**（高德返回的 `distance` 也是直线距离）：

- 不是步行距离；
- 不是驾车距离；
- 不是通勤时间；
- 不能直接说“最近医院开车 5 分钟”。

如果要真实路线距离/时间，需要再调高德 **路径规划 API**：

```text
https://restapi.amap.com/v3/direction/driving
  ?key=...
  &origin=经度,纬度
  &destination=经度,纬度
```

这会额外消耗“基础 LBS 服务”配额（个人认证 150,000 次/月），并按返回的 `distance` / `duration` 展示。

### 5.5 课程演示建议

- 优先让用户**手动选择区域**，比浏览器定位稳定；
- 如果使用定位，必须显示精度，并允许手动修正；
- 文案写“直线距离参考”，不要写“最近/最快”；
- 答辩时主动说明“定位有误差，距离是直线距离”，比被老师问出来更好。

## 六、已知限制

1. **本地只有 10 家医院**：不配置高德 Key 时不是完整 POI 库；
2. **坐标是近似值**：不能用于真实导航，只能演示排序；
3. **坐标系差异**：浏览器定位是 WGS-84，高德是 GCJ-02；前端已做转换，但浏览器定位本身仍可能不准；
4. **没有路线规划**：当前只打开地图标记页，不计算驾车/公交路线；
5. **没有逆地理编码**：页面只显示“当前位置/上次位置”，不显示具体街道地址；
6. **保存位置是单机级**：后端 `saved_location` 只有一条记录，多用户会共用；正式上线需按用户隔离。

---

## 七、答辩时怎么讲

> 我们没有把地图 Key 写死在前端。用户点“医院推荐”后，可以先定位，也可以直接输入“旗山校区”这类具体地点；后端用 Haversine 计算直线距离并排序。默认走本地 10 家医院，所以离线也能演示；配置高德 Web 服务 Key 后，同一接口会自动切换成真实周边医院 POI，并可用输入提示 API 解析任意地址。地图跳转用高德 URI，不需要 JS SDK。位置保存采用“本地 localStorage + 后端单行兜底”，解决 file:// 与 localhost 存储隔离的问题；正式上线会按用户隔离。挂号方式不是一句“去公众号”，而是点开后显示官方渠道、放号时间、预约步骤和注意事项。

## 九、医院服务页 / 挂号指引 / 院内导航

### 9.1 入口

```text
报告 → 医院推荐 → 点选医院 → 医院服务页
                              ├─ 挂号指引
                              └─ 院内导航
```

- 报告卡不再放“挂号指引/院内导航”全局按钮；
- 医院列表卡片整卡可点，去掉卡片内小按钮；
- 医院服务页带医院、院区、推荐科室、地址；
- 挂号指引/院内导航都基于“已选医院 + 推荐科室”。

### 9.2 挂号指引

- 10 家医院官方渠道、放号时间、预约步骤、注意事项；
- 可复制挂号信息；
- 明确写“只提供官方渠道指引，不提供真实号源”；
- 不接真实号源、支付、医保。

### 9.3 院内导航

- 目前 6 家：协和旗山、协和于山、省立东街、省立金山、附一茶亭、省人民；
- 楼层/科室位置按医院公开信息整理，房间几何位置仍为示意；
- 其他医院没有详细室内图，点击后明确提示“暂无该医院的详细院内导航数据”，不生成假路线；
- 路线按入口/目的地动态生成，同层目的地不强制绕行大厅；
- 1F 门诊大厅 + 目标楼层示意图；
- 楼层墙体为封闭轮廓，入口处留门洞；
- 路线用蓝色实线连接，不使用虚线；
- 门只保留带边框的文字标签，不加图标；
- 电梯/科室/收费/药房/服务台保留圆形类型图标（白底彩色描边 + 字），同时保留文字标签；
- 不显示图例；蓝色实线即推荐路线；
- 入口/目的地选择；
- 预置路线步骤；
- 手动选“我现在在”，不做室内实时定位；
- 楼层图标注“示意，以院内导视为准”。

试点导航的科室楼层已按官方公开信息修正：

- 省立东街：内科诊区 3F → **4F**；
- 附一茶亭：内科诊区 4F → **2F**；
- 协和旗山：保留 1F/3F 示意，但注明“仅部分科室公开”；
- 协和于山：内科诊区 **4F**，收费处在 1B（本图未覆盖）；
- 省立金山：内科诊区 **3F**，药房/收费 1F；
- 省人民：脾胃病科/消化内镜 **3F**，1F 收费/药房以现场为准。
