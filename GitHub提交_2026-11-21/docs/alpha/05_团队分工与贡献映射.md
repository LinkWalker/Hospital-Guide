# 门诊排队｜团队分工与贡献映射

> 说明：这是一份“按可核验产出认领”的建议稿，不是把已经完成的工作重新分配。  
> 时间压缩到最后 48 小时单点集成，是为了效率；但团队作业需要每个人有可见贡献。  
> 下面的权重和任务可以调整，前提是：**认领人要在截止前补上证据**（commit/PR、文档段落、测试输出、截图）。

---

## 一、分工原则

1. **不按人头平均分**：按模块、文档、测试、截图的实际产出分；
2. **答辩和 Vlog 由丘南星统一负责**，不再拆给其他人；
3. 每个人至少有一块“能独立验收”的东西；
4. 只挂名、没有产出的，不写“独立完成”，最多写“参与评审/提供资料”；
5. 最后 48 小时由丘南星统一联调、打包，避免多人同时改 main。

## 四、最低证据标准

每个人至少满足一项，否则不建议写“独立完成”：

- 一个可指向的 commit / PR；
- 一段进入最终文档的内容；
- 一条新增测试或一次联调记录；
- 一张带日期的截图；
- 一次试用/评审记录（含问题清单）。

推荐在 `alpha冲刺/最终交付材料_2026-11-18/` 下按姓名建子目录放证据，例如：

```text
evidence/
├── 陈嘉俊_测试试用/
├── 薛强龙_文档/
├── 李韩远_急症回归/
├── 梁洪睿_API联调/
└── ...
```

---

## 五、为什么这样分

- 时间只有 4 天集中冲刺，多人同时改 main 的协调成本太高；
- 答辩、Vlog、最终打包必须一个人统一口径，否则版本会乱；
- 其他人做“可独立交付”的测试、文档、模块走查，既不会互相阻塞，也能留下证据；
- 这不是“平均分功劳”，而是“每人认领一块能验收的产出”。

---

## 六、答辩时的说法

建议统一口径：

> 这次冲刺时间很短，我们采用“少数人集中集成 + 其他人认领独立模块”的方式。  
> 丘南星负责统筹、联调、答辩和 Vlog；其他同学分别负责测试、文档、后端模块和前端页面。  
> 所有贡献以 commit、文档、测试和截图为准。

不要这样说：

- “大家都做了很多”（没有证据）；
- “某同学独立完成了整个模块”（如果实际不是）；
- 把答辩/Vlog 说成集体完成（实际由丘南星负责）。
