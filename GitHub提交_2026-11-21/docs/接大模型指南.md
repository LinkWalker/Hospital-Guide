# 接入真实大模型指南（OpenAI 兼容协议）

> 适用版本：`v0.1.0-alpha` 之后
> 目标：不改业务代码，只改 `.env` 四个变量，就能把「本地 mock」切成真实大模型；
> 失败时自动降级，不影响演示。

---

## 一、先看结论：三步接入

### 第 1 步：复制配置

在 `medical-triage-backend` 目录：

```powershell
copy .env.example .env
```

### 第 2 步：填四个变量

打开 `.env`，把：

```ini
LLM_PROVIDER=mock
```

改成：

```ini
LLM_PROVIDER=openai
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-你的Key
LLM_MODEL=deepseek-chat
LLM_TIMEOUT=30
LLM_MAX_RETRIES=1
```

### 第 3 步：自检

```powershell
python scripts/check_llm.py
```

看到：

```text
结果：成功。真实模型返回已通过科室白名单 / Schema 校验。
```

就说明接通了。启动服务：

```powershell
uvicorn app.main:app --reload --port 8000
```

打开 `http://127.0.0.1:8000`，报告右上角会显示「真实模型 · 模型名」。

> 如果自检失败，报告右上角会显示「模型超时 · 已降级」，服务不会 500。
> 具体排查见本文第七节。

## 二、支持的平台与配置

所有平台都走 **OpenAI 兼容协议**，所以代码只认 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 三个变量。模型名以平台控制台当前提供的为准。

| 平台 | `LLM_BASE_URL` | `LLM_MODEL` 示例 | Key 申请 |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | https://platform.deepseek.com/ |
| 豆包（火山方舟） | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-seed-1-6` 或控制台的接入点 ID | https://console.volcengine.com/ark/ |
| Kimi（Moonshot） | `https://api.moonshot.cn/v1` | `moonshot-v1-8k`（以控制台为准） | https://platform.moonshot.cn/ |
| 通义千问（DashScope 兼容模式） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | https://dashscope.console.aliyun.com/ |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | https://open.bigmodel.cn/ |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | https://platform.openai.com/ |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` | 不需要，`LLM_API_KEY=ollama` 占位 |

## 三、它是怎么接进去的

```text
用户输入
  ↓
Orchestrator（编排器）
  ↓
NLU 信息抽取（规则为主）
  ↓
急症拦截（纯代码，不经过大模型）
  ↓
多轮追问（状态机）
  ↓
RAG 检索（规则库 + 向量证据）
  ↓
LLMGateway.generate_triage()
  ├─ 真实模型：POST {LLM_BASE_URL}/chat/completions
  │    ↓
  │  _validate_content()
  │    ├─ JSON 解析（容忍 ```json 包裹）
  │    ├─ 科室别名/模糊归一化（心内科 → 心血管内科）
  │    ├─ 科室白名单校验（未知科室直接拒绝）
  │    ├─ Pydantic Schema 校验
  │    └─ 失败 → 重试 → 仍失败 → 降级 mock
  └─ mock：本地规则模板（无 Key 也能演示）
  ↓
结构化报告（科室/依据/挂号/导航/话术/提醒/免责声明）
```

关键代码：

- `app/core/llm_gateway.py`：OpenAI 兼容调用、重试、降级、输出校验；
- `app/modules/dept_matcher.py`：科室别名/模糊匹配；
- `app/modules/orchestrator.py`：把模型结果组装成 API 响应；
- `scripts/check_llm.py`：连通性自检。

### 3.1 请求格式

代码发送的是标准 OpenAI Chat Completions 请求：

```json
{
  "model": "deepseek-chat",
  "messages": [
    {"role": "system", "content": "你是医院智能导诊助手的结构化输出模块……"},
    {"role": "user", "content": "请根据以下结构化症状信息输出导诊 JSON……"}
  ],
  "temperature": 0.2,
  "response_format": {"type": "json_object"}
}
```

> 不是所有平台都支持 `response_format`。如果平台报 400，可在 `llm_gateway._openai_chat` 里临时去掉该字段；
> 代码本身有 JSON 抽取兜底，不强制依赖 `response_format`。

### 3.2 输出校验（防幻觉）

模型必须返回：

```json
{
  "recommended_department": "心血管内科",
  "alternative_departments": ["呼吸内科", "急诊科"],
  "basis": ["……"],
  "booking_guide": "……",
  "navigation": "……",
  "dialogue_script": "……",
  "reminders": ["……"],
  "disclaimer": "仅供参考，不替代医生诊断"
}
```

校验规则：

1. `recommended_department` 必须能归一化到白名单；否则整条结果拒绝，降级 mock；
2. `alternative_departments` 能归一则保留，不能归一则丢弃；
3. 数组字段如果被模型写成字符串，自动转成单元素数组；
4. 最终必须通过 Pydantic `TriageResult`；
5. 失败最多重试 `LLM_MAX_RETRIES` 次，仍失败则 `degraded=true` + mock 结果。

## 四、怎么验证接通了

### 4.1 命令行自检

```powershell
python scripts/check_llm.py
```

成功输出示例：

```text
provider : openai
model    : deepseek-chat
base_url : https://api.deepseek.com/v1
api_key  : 已配置（不显示）
...
推荐科室   : 心血管内科
是否降级   : False
结果：成功。真实模型返回已通过科室白名单 / Schema 校验。
```

### 4.2 健康检查

```powershell
curl http://127.0.0.1:8000/api/v1/health
```

返回里应看到：

```json
{
  "llm_provider": "openai",
  "llm_model": "deepseek-chat",
  "llm_ready": true
}
```

### 4.3 页面验证

1. 打开 `http://127.0.0.1:8000`；
2. 输入「我胸口闷，已经三天了，我是成年男性」；
3. 出报告后看标题右侧：
   - `真实模型 · deepseek-chat` = 成功；
   - `模型超时 · 已降级` = 真实模型失败，已走 mock；
   - `本地稳定模式` = 当前是 mock 配置。

### 4.4 10 条回归（答辩前建议跑）

至少覆盖：

1. 普通症状 → 报告；
2. 信息不全 → 追问；
3. 多轮补齐 → 报告；
4. 改口 → 重新收集；
5. 急症词 → 拦截（不经过模型）；
6. 老人/儿童/孕妇；
7. 超长输入（4000 字边界）；
8. 空输入（422）；
9. 模型返回别名科室（心内科）→ 归一化；
10. 模型返回未知科室 → 拒绝并降级。

把结果写进 `docs/alpha/llm-regression.md`，附日期、模型名、通过数、失败原因。

## 五、安全与合规

1. **不要把 Key 提交到 GitHub**。`.env` 已在 `.gitignore`；只提交 `.env.example`。
2. **不要在博客/截图里露出 Key**。截图前检查终端和 `.env`。
3. **Key 泄露后立即在平台控制台撤销并重新生成**。
4. **模型输出不是诊断**。报告始终带免责声明；急症拦截不经过模型。
5. **历史记录含症状描述**，属于敏感信息：
   - 默认保留 30 天；
   - 用户可单条删除/全部清空；
   - 部署时用 HTTPS，限制数据库文件权限；
   - 不要把生产数据库提交到仓库（`data/` 已忽略）。
6. **生产环境建议**：
   - Key 放环境变量/密钥管理服务，不写代码；
   - 给模型调用加超时、重试、限流、日志脱敏；
   - 监控 `degraded` 比例，超过阈值告警。

## 六、成本与性能建议

| 项目 | 建议 |
|---|---|
| 模型选择 | 课程演示用 `deepseek-chat` / `qwen-plus` / `glm-4-flash` 即可，不必上最贵模型 |
| 温度 | 保持 `0.2`，降低随机性 |
| 证据 | 只传 top3–top5 检索证据，别把整库塞进 Prompt |
| 超时 | 国内 API 建议 30s；本地 Ollama 建议 120s |
| 重试 | 默认 1 次；失败降级，不要让用户等太久 |
| 缓存 | 同一症状+证据可做短期缓存，节省成本（Beta 再做） |
| 并发 | 课程演示单机足够；上线多实例时配 Redis + 限流 |

## 七、常见问题排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `401 Unauthorized` | Key 错误/过期/多了空格 | 重新复制 Key；检查 `.env` 是否有引号/空格 |
| `404 Not Found` | Base URL 多了 `/chat/completions`，或模型名/接入点不对 | Base URL 只填到 `/v1` 或 `/api/v3`；豆包填 `ep-...` |
| `400 response_format` | 平台不支持 JSON mode | 临时去掉 `response_format` 字段 |
| `429 Too Many Requests` | 限流/余额不足 | 降低频率、充值、换模型 |
| 超时/连接失败 | 网络/代理/防火墙 | 先用 curl 测 Base URL；本地 Ollama 确认 `ollama serve` |
| JSON 解析失败 | 模型返回了 Markdown/解释文字 | 代码会抽取第一个 `{...}`；仍失败则降级 |
| 科室被拒绝 | 模型返回了白名单外科室 | 在 `department_aliases.json` 补别名；或让模型从枚举里选 |
| 一直是 mock | `LLM_PROVIDER` 没改，或 `.env` 不在启动目录 | 确认启动目录是 `medical-triage-backend`；重启服务 |
| 页面显示降级 | 真实调用失败 | 看后端日志的 `LLM 生成失败` 行；跑 `check_llm.py` |

### 7.1 用 curl 直连测试

```powershell
curl https://api.deepseek.com/v1/chat/completions `
  -H "Authorization: Bearer sk-你的Key" `
  -H "Content-Type: application/json" `

```

```

## 八、答辩时怎么讲

建议用这一段：

> 我们的 Agent 不是“把症状直接丢给大模型”。急症拦截是纯代码规则，不经过模型；模型只负责在检索证据和白名单约束下做结构化生成。模型返回的科室会先做别名归一化，再经过白名单和 Pydantic 校验；失败会自动重试并降级到本地规则模板。这样既能用真实模型提升表达质量，又不会因为模型幻觉或超时让系统不可用。

如果老师问“真实模型通过率”：

> 我们跑了 10 条固定回归，通过【N】条；失败的全部走降级，用户仍然能拿到可用结果。具体失败原因和截图在 `docs/alpha/llm-regression.md`。

不要背“100% 准确”；说清楚“可用率”和“降级率”更可信。
