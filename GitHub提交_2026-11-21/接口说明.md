# 后端接口说明（前端对接用）

> Base URL：`http://<后端地址>:8000`
> 交互模式：多轮对话，前端用同一个 `session_id` 串联整段对话。

---

## 1. 发起/继续对话

`POST /api/v1/chat`

### 请求体

```json
{
  "session_id": "任意字符串，前端自己生成",
  "message": "用户输入的症状描述"
}
```

### 响应（type 字段区分三种情况）

#### ① type = "question" —— 系统在追问

```json
{
  "session_id": "abc",
  "type": "question",
  "message": "这个症状大概持续多长时间了？",
  "data": { "collected": { ... } }
}
```
前端做法：把 `message` 显示出来，让用户回答，再把回答作为新的 `message` 发下一条请求。

#### ② type = "result" —— 给出导诊结果

```json
{
  "session_id": "abc",
  "type": "result",
  "message": "根据您描述的症状，建议挂【心血管内科】...",
  "data": {
    "recommended_department": "心血管内科",
    "alternative_departments": ["呼吸内科", "急诊科"],
    "basis": ["胸痛胸闷...", "（检索依据）"],
    "booking_guide": "可前往医院官方挂号平台或到院挂号窗口...",
    "navigation": "挂号完成后，请根据院内导视前往...",
    "dialogue_script": "您好，我最近胸部不舒服，症状是闷...",
    "reminders": ["建议携带既往病历", "如症状加重请及时就医"],
    "disclaimer": "仅供参考，不替代医生诊断",
    "llm_provider": "openai",
    "llm_model": "deepseek-chat",
    "degraded": false,
    "fallback_reason": ""
  }
}
```
前端做法：展示主推科室、备选科室、判断依据、挂号指引、沟通话术（可复制按钮）、就医提醒。**底部固定显示 disclaimer**。

> `llm_provider` / `llm_model` / `degraded` 用于前端标注“真实模型 / 本地稳定模式 / 已降级”。
> `degraded=true` 时说明真实模型失败、已回退 mock，演示不受影响，但答辩时应如实说明。

#### ③ type = "urgent" —— 急症拦截

```json
{
  "session_id": "abc",
  "type": "urgent",
  "message": "您描述的症状属于紧急情况，请立即...拨打 120 急救电话。",
  "data": { "level": "emergency", "label": "紧急", "keyword": "胸痛伴出冷汗" }
}
```
前端做法：醒目红色提示，建议拨打 120，终止常规对话。

## 2. 查询会话状态

`GET /api/v1/session/{session_id}`

返回当前会话收集到的信息和历史记录，用于前端刷新页面后恢复对话。

---

## 3. 健康检查

`GET /api/v1/health`

返回 `{"status":"ok", "llm_provider":"openai", "llm_model":"deepseek-chat", "llm_ready":true, "history_enabled":true, ...}`，前端用来判断后端是否在线、模型是否配置完整。

## 3.5 会话历史（Alpha 新增）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/history?limit=20&offset=0` | 历史列表，按更新时间倒序；返回 `items` + `total` |
| GET | `/api/v1/history/{id}` | 历史详情：`messages` + `result`，不返回内部 `state` |
| POST | `/api/v1/history/{id}/restore` | 恢复会话到内存，返回 `session_id` + `messages`，可继续对话 |
| DELETE | `/api/v1/history/{id}` | 删除单条，成功 204 |
| DELETE | `/api/v1/history` | 清空全部，成功 204 |

列表项字段：

```json
{
  "id": "uuid",
  "title": "我胸口闷",
  "status": "ready",
  "department": "心血管内科",
  "urgent_level": null,
  "message_count": 6,
  "created_at": "2026-11-17T20:00:00",
  "updated_at": "2026-11-17T20:01:00"
}
```

> 隐私：历史默认保存 30 天，用户可单条删除/全部清空；`HISTORY_ENABLED=false` 可关闭。
> 前端在后端不可用时自动回退浏览器 `localStorage`，离线演示仍有记录。

## 3.6 医院推荐（Alpha 新增）

`GET /api/v1/hospitals/nearby?lat=26.074&lng=119.296&limit=6`

返回按距离排序的医院列表：

```json
{
  "origin": {"lat": 26.074, "lng": 119.296},
  "source": "local",
  "message": "",
  "items": [
    {
      "name": "福建省立医院",
      "level": "三甲",
      "address": "福州市鼓楼区东街134号",
      "latitude": 26.0813,
      "longitude": 119.2986,
      "distance_km": 0.8,
      "registration_channel": "114预约挂号平台/医院公众号",
      "registration_url": "",
      "map_url": "https://uri.amap.com/marker?position=119.298600,26.081300&name=...",
      "source": "local"
    }
  ]
}
```

- `lat` / `lng` 必填，纬度 -90~90、经度 -180~180；
- `limit` 最大 20；
- `source=amap` 表示来自高德周边搜索，`local` 表示本地医院表；
- 前端定位失败时会用福州市中心坐标兜底，并允许手动选择区域。

### 3.7 解析用户输入的地点

`GET /api/v1/hospitals/geocode?address=旗山校区`

用高德输入提示 API 把口语地点解析成 GCJ-02 坐标：

```json
{
  "label": "福州大学旗山校区(西门)",
  "address": "上街镇乌龙江北大道2号",
  "latitude": 26.057439,
  "longitude": 119.193555,
  "source": "amap"
}
```

- 需要配置 `AMAP_API_KEY`，否则返回 503；
- 解析失败返回 404；
- 前端解析成功后会询问用户是否保存该位置到 `localStorage`，下次可直接使用。

### 3.8 上次使用的医院推荐位置

单机演示级，后端只保存一条记录：

```text
GET    /api/v1/preferences/location   # 无记录返回 204
PUT    /api/v1/preferences/location   # 保存/覆盖
DELETE /api/v1/preferences/location   # 删除
```

请求体：

```json
{
  "label": "福州大学旗山校区",
  "address": "闽侯县上街镇乌龙江北大道2号",
  "latitude": 26.057439,
  "longitude": 119.193555
}
```

前端同时写入 `localStorage`，本地没有时从后端取；用于解决 `file://` 与 `localhost` 存储隔离。

## 4. 前端对接示例（JavaScript）

```javascript
async function sendMessage(sessionId, text) {
  const resp = await fetch("http://127.0.0.1:8000/api/v1/chat", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ session_id: sessionId, message: text })
  });
  const data = await resp.json();

  if (data.type === "question") {
    // 显示追问，等用户回答
    showBubble(data.message);
  } else if (data.type === "result") {
    // 渲染导诊结果卡片
    showResultCard(data.data);
  } else if (data.type === "urgent") {
    // 红色急症提示
    showUrgentBanner(data.message);
  }
}

// 首次对话时生成一个 session_id（如 uuid）
const sessionId = crypto.randomUUID();
```

---

## 5. 注意事项

- 前端**不要**自己判断科室，科室完全由后端返回；
- 每次请求都带上同一个 `session_id`，多轮对话状态由后端维护；
- 返回的 `disclaimer` 字段必须展示在结果页底部；
- 接口在线调试：后端启动后访问 `http://127.0.0.1:8000/docs`，可直接在网页上发请求看返回。
