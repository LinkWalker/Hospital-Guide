# 初版原型归档与演进说明（林豪）

> 归档内容：肖志渊的微信小程序初版原型（v1，2026-09）
> 状态：**已废弃，仅作归档**（当前版本为墨刀设计稿 + 真实后端）
> 归档人：林豪（前端）｜上传位置：`prototypes/v1小程序初版/` + 本说明

## 一、v1 是什么

肖志渊在项目初期用微信小程序（原生）做的**可运行前端原型**，用于第一次作业答辩演示。
代码结构：

```
v1小程序/
├── app.js / app.json / app.wxss
├── pages/
│   ├── start/      启动页（点"开始导诊"跳对话页）
│   ├── index/      首页（欢迎/入口）
│   ├── input/      对话页（聊天记录、输入框、报告卡片）
│   ├── emergency/  急症页（拨打120 / 返回修改）
│   └── logs/       日志页
├── utils/util.js
└── project.config.json / sitemap.json
```

## 二、v1 的交互逻辑（前端 mock，写死）

`pages/input/input.js` 中 `mockBackendLogic()` 是**写死的前端假后端**：

| 用户输入 | v1 行为 |
|---|---|
| 含"胸痛"或"喘不上气" | `wx.navigateTo` 跳急症页 |
| 恰好等于"肚子疼" | 固定追问："请问是上腹部还是下腹部？是绞痛还是隐痛？" |
| 其他任意输入 | 固定报告："消化内科" + 固定话术 |

配合 `setTimeout(…, 1000)` 模拟"思考中"加载态。

## 三、v1 的贡献（值得保留的部分）

1. **页面结构定型**：启动页 → 对话页 → 急症页 + 报告卡片，这一结构被 v2（墨刀）继承
2. **交互流程验证**：急症拦截跳转、追问气泡、报告卡片展示、一键复制话术的交互原型跑通了
3. **答辩演示**：第一次作业答辩用 v1 现场演示"痛点→方案"
4. **规则先行意识**：把"胸痛/喘不上气"当高危词、把追问当固定问答，验证了"规则驱动"的思路

## 四、v1 的局限（为什么演进）

| 问题 | v1 | 现版（v2） |
|---|---|---|
| 分诊逻辑 | 前端写死 3 个分支 | 真实后端：425 条规则 / 1775 关键词 + 向量证据 |
| 追问 | 只对"肚子疼"一个词固定追问 | 多轮追问状态机（部位→性质→时长→人群，去重、上限、改口） |
| 急症 | 关键词硬编码在页面里 | 纯代码规则引擎 417 条红旗词（Ⅰ/Ⅱ级），全量回归测试 |
| 报告 | 固定"消化内科" | 规则命中 + LLM 结构化生成 + 科室白名单枚举校验 |
| 架构 | 无后端、不可扩展 | FastAPI 后端 + 知识库 + mock/真实大模型双模式 |
| 可维护 | 规则改一个词要改代码 | 知识 JSON 为唯一编辑源，导入脚本幂等 |

## 五、演进路线（供答辩陈述）

```
v1 小程序前端 mock（肖志渊，可演示）
  ↓ 页面结构与交互被继承
v2 墨刀设计稿（问诊小程序，交互/视觉设计）
  ↓ 真实实现
v2.1 Web 前端 + FastAPI 后端（Agentic RAG 四步流程 + 44 项测试）
```
