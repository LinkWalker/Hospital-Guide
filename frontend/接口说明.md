# 后端接口说明（前端对接用）

> Base URL：`http://<后端地址>:8000`
> 交互模式：多轮对话，前端用同一个 `session_id` 串联整段对话。

---

## 1. 发起/继续对话

`POST /api/v1/chat`

### 请求体

```json
{
  "session_id": "任意字符串，前端自己生成",
  "message": "用户输入的症状描述"
}
```

### 响应（type 字段区分三种情况）

#### ① type = "question" —— 系统在追问

```json
{
  "session_id": "abc",
  "type": "question",
  "message": "这个症状大概持续多长时间了？",
  "data": { "collected": { ... } }
}
```
前端做法：把 `message` 显示出来，让用户回答，再把回答作为新的 `message` 发下一条请求。

#### ② type = "result" —— 给出导诊结果

```json
{
  "session_id": "abc",
  "type": "result",
  "message": "根据您描述的症状，建议挂【心血管内科】...",
  "data": {
    "recommended_department": "心血管内科",
    "alternative_departments": ["呼吸内科", "急诊科"],
    "basis": ["胸痛胸闷...", "（检索依据）"],
    "booking_guide": "可前往医院官方挂号平台或到院挂号窗口...",
    "navigation": "挂号完成后，请根据院内导视前往...",
    "dialogue_script": "您好，我最近胸部不舒服，症状是闷...",
    "reminders": ["建议携带既往病历", "如症状加重请及时就医"],
    "disclaimer": "仅供参考，不替代医生诊断"
  }
}
```
前端做法：展示主推科室、备选科室、判断依据、挂号指引、沟通话术（可复制按钮）、就医提醒。**底部固定显示 disclaimer**。

#### ③ type = "urgent" —— 急症拦截

```json
{
  "session_id": "abc",
  "type": "urgent",
  "message": "您描述的症状属于紧急情况，请立即...拨打 120 急救电话。",
  "data": { "level": "emergency", "label": "紧急", "keyword": "胸痛伴出冷汗" }
}
```
前端做法：醒目红色提示，建议拨打 120，终止常规对话。

---

## 2. 查询会话状态

`GET /api/v1/session/{session_id}`

返回当前会话收集到的信息和历史记录，用于前端刷新页面后恢复对话。

---

## 3. 健康检查

`GET /api/v1/health`

返回 `{"status":"ok", ...}`，前端用来判断后端是否在线。

---

## 4. 前端对接示例（JavaScript）

```javascript
async function sendMessage(sessionId, text) {
  const resp = await fetch("http://127.0.0.1:8000/api/v1/chat", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ session_id: sessionId, message: text })
  });
  const data = await resp.json();

  if (data.type === "question") {
    // 显示追问，等用户回答
    showBubble(data.message);
  } else if (data.type === "result") {
    // 渲染导诊结果卡片
    showResultCard(data.data);
  } else if (data.type === "urgent") {
    // 红色急症提示
    showUrgentBanner(data.message);
  }
}

// 首次对话时生成一个 session_id（如 uuid）
const sessionId = crypto.randomUUID();
```

---

## 5. 注意事项

- 前端**不要**自己判断科室，科室完全由后端返回；
- 每次请求都带上同一个 `session_id`，多轮对话状态由后端维护；
- 返回的 `disclaimer` 字段必须展示在结果页底部；
- 接口在线调试：后端启动后访问 `http://127.0.0.1:8000/docs`，可直接在网页上发请求看返回。
