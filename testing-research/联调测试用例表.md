# 前后端联调测试用例表

> 接口基础：`POST /api/v1/chat`，请求体 `{ "session_id": "xxx", "message": "用户输入" }`
> 响应类型：`question`（追问）/ `result`（导诊结果）/ `urgent`（急症拦截）
> 联调环境：后端 `uvicorn app.main:app --reload`，前端任意调用方。

---

## 一、正常导诊流程

| 编号 | 场景 | 输入 message | 期望 type | 期望关键校验点 |
|------|------|-------------|-----------|---------------|
| TC-01 | 一句话完整主诉直出结果 | "我胸口闷痛，喘不上气，持续三天，我是成年人" | result | recommended_department = 心血管内科；basis 非空；disclaimer 存在 |
| TC-02 | 腹痛腹泻直出消化内科 | "我肚子痛拉肚子两天了" | result 或 question | 若 result，科室应为消化内科/全科；若 question，应追问缺失字段 |
| TC-03 | 皮肤过敏起疹 | "我全身起风团，很痒" | result | 科室为皮肤科/变态反应科 |
| TC-04 | 儿童症状优先儿科 | "我家孩子发烧咳嗽两天了" | result 或 question | 若 result，科室应为儿科 |
| TC-05 | 妇科症状 | "我月经不调，痛经严重" | result | 科室为妇科 |
| TC-06 | 新增规则库命中（高血压） | "我高血压好几年了，最近头晕" | result 或 question | 若 result，科室为心血管内科 |
| TC-07 | 新增规则库命中（变态反应） | "每年春天就打喷嚏流眼泪，鼻子痒" | result | 科室为变态反应科/呼吸内科 |
| TC-08 | 新增规则库命中（乳腺） | "乳头有血性溢液" | result | 科室为乳腺外科 |

## 三、多轮追问状态机

| 编号 | 场景 | 对话序列 | 期望 |
|------|------|---------|------|
| TC-30 | 首轮模糊输入触发追问部位 | "不舒服" → ? | 首轮 type=question，问部位 |
| TC-31 | 逐轮补全后出结果 | "不舒服" → "肚子痛" → "拉肚子三天" → ? | 信息补齐后 type=result |
| TC-32 | 追问不重复问同一字段 | 连续两轮答"肚子痛" | 第二轮不应再问部位 |
| TC-33 | 中途改口：先胸痛后肚子痛 | "我胸口闷" → "搞错了，其实是肚子痛拉肚子" | 最终科室应为消化内科，不是心血管内科 |
| TC-34 | 追问中途触发急症拦截 | "肚子不舒服" → "我突然大出血" | 第二轮直接 urgent，不再追问 |
| TC-35 | 追问上限兜底 | "不舒服" → "就难受" → "浑身不对劲"（max=3） | 第三轮必须 result，不能继续 question |
| TC-36 | 会话隔离 | session-A 说肚子痛，session-B 说胸痛 | 两会话结果互不影响 |

## 四、异常与边界输入

| 编号 | 场景 | 输入 message | 期望行为 |
|------|------|-----------|---------|
| TC-40 | 空字符串 | "" | 不报错，正常返回 question/result |
| TC-41 | 纯空格 | "   " | 不报错 |
| TC-42 | 纯标点 | "。。。？！" | 不报错 |
| TC-43 | 超长文本（3000字） | 含"胸口闷喘不上气三天"的长段落 | 不崩溃，能提取关键症状 |
| TC-44 | 无意义字符 | "asdfghjkl" | 不报错，走追问兜底 |
| TC-45 | 特殊字符/emoji | "我😷肚子痛🤒" | 不报错 |
| TC-46 | 极短输入"头痛" | "头痛" | 能匹配神经内科 |

## 五、LLM 结构化输出与科室枚举校验

> 切到真实大模型（LLM_PROVIDER=openai，填好 Key）后联调。

| 编号 | 场景 | 校验点 |
|------|------|--------|
| TC-50 | 正常返回科室 | recommended_department 必须在白名单27科室内 |
| TC-51 | **防编造科室** | 人为让模型输出"肿瘤科"，后端应拒绝/降级，不返回该科室 |
| TC-52 | 数组字段容错 | alternative_departments/basis/reminders 必须是数组，模型返回字符串时自动归一 |
| TC-53 | 非JSON输出 | 模型返回带解释文字的JSON，后端能抽取{}块 |
| TC-54 | 证据不越界 | basis 只能来自检索资料，不出现"建议做CT/吃某药"等治疗建议 |
| TC-55 | disclaimer 兜底 | 返回必含"仅供参考，不替代医生诊断" |

## 六、会话与健康检查接口

| 编号 | 接口 | 期望 |
|------|------|------|
| TC-60 | GET /api/v1/health | 返回 status=ok，llm_provider 与 .env 一致 |
| TC-61 | GET /api/v1/session/{id} | 已会话返回状态；不存在返回 404 |
| TC-62 | 重启后会话丢失（memory模式） | 重启服务后旧 session 404（预期行为） |

## 七、联调通过标准

- [ ] 全部 I 级急症用例（TC-10~16）100% 命中 emergency，文案含"120"
- [ ] 追问上限兜底（TC-35）不无限问
- [ ] 中途改口（TC-33）结果跟随最新主诉
- [ ] LLM 枚举校验（TC-51）不通过时后端有降级或报错，不静默放行编造科室
- [ ] 30 个自动化单测全部通过（`pytest tests/`）
- [ ] 异常输入（TC-40~46）无 500 错误
